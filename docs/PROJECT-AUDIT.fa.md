# بررسی پروژه و نقشه اجرایی — ۱۳ اکتبر ۲۰۲۶

## وضعیت واقعی پیش از تغییر

- چهار پروژه net8.0: Domain، Application، Infrastructure و Web؛ UI از نوع ASP.NET Core Razor Pages است، نه Blazor. Runtime نصب‌شده ASP.NET Core 8.0.31 و SDK ماشین 10.0.401 است.
- EF Core 8.0.31 با SQL Server؛ یک migration اولیه 20261012072050_mig-init. تنظیم توسعه به FriendShipDb روی SQL Server محلی اشاره می‌کند. برنامه migration را خودکار اجرا نمی‌کند.
- احراز هویت سفارشی کوکی با ASP.NET Data Protection، SecurityStamp و PasswordHasher استاندارد Identity؛ ASP.NET Core Identity کامل استفاده نشده است. ایمیل در ثبت‌نام فعلی اجباری است.
- هویت مهمان در کوکی Secure/HttpOnly و محافظت‌شده با انقضای ۳۰ روز؛ مدیریت بازی فقط با حساب مالک انجام می‌شود. Razor POSTها antiforgery دارند.
- سرویس‌های مستقل Auth، Room، Play، Results، Stats، Profile، Achievement و Admin موجودند. هیچ API خارجی، SignalR یا موتور AI فعال وجود ندارد.
- مدل موجود: User، Category/Question/Option، Room/RoomQuestion/Option/StatusChange و Participant/Answer؛ سؤال‌ها در Room snapshot می‌شوند. unique indexهای شرکت‌کننده/بازدیدکننده و پاسخ/سؤال و concurrency tokenهای پاسخ و تکمیل از نقاط قوت‌اند.
- جریان واقعی: Account → Rooms/Create → Rooms/Manage (پاسخ مرجع و انتشار) → Lobby/Join → Play → Results/Share؛ Insights فقط برای مالک. پاسخ‌ها مرحله‌به‌مرحله در سرور ذخیره می‌شوند.
- امتیاز کلاسیک ۱۰۰ برای پاسخ صحیح؛ درصد از تعداد صحیح بر تعداد کل سؤال‌ها. حالت سرعتی هم موجود است. رتبه‌بندی فعلی سرعت را در شکستن تساوی دخیل می‌کند.
- UI اختصاصی CSS و JS ساده با فونت محلی Vazirmatn و RTL؛ Bootstrap/jQuery فقط در layout اولیه. دو PNG شفاف boy و cat حدود ۱.۶MB هر کدام موجودند و قابل استفاده‌اند.
- صفحه شروع، Login/Register و OwnerAnswers قدیمی بخش‌های نمایشی‌اند؛ منو مسیرهای ناموجود Achievements و Account/Login دارد. کارت اشتراک فعلی صفحه HTML عمومی است و تصویر قابل دانلود تولید نمی‌کند.
- تستی در solution نیست. build اولیه بدون خطا/هشدار موفق بود. پوشه انتخابی مخزن Git نیست، بنابراین diff/status گیت در دسترس نیست.

## مشکلات و ریسک‌ها

سؤال مستقیم برای صاحب و دوست یکسان است؛ چند اتاق، ظرفیت ۵۰ و انقضای ۷ روز با بازی شخصی دائمی سازگار نیستند. کد ۶ کاراکتری برای لینک اصلی کافی نیست. آمار فعلی با کمتر از ۳ یا ۵ نمونه حتی مقادیر توصیفی را پنهان می‌کند. محدودکننده حافظه‌ای در Sweep پنجره یک endpoint را به همه کلیدها اعمال می‌کند. مهاجرت schema باید روی دیتابیس آزمایشی بررسی شود؛ داده واقعی نباید خودکار دست‌کاری شود. حذف کوکی مهمان امکان شناسایی شرکت‌کننده قبلی را از بین می‌برد؛ محدودیت نرخ جایگزین شناسایی قطعی انسان نیست.

## تصمیم و برنامه توسعه

۱. معماری و Room حفظ می‌شوند. به User نام کاربری اختیاری برای سازگاری حساب‌های قبلی، لینک عمومی تصادفی و اشاره‌گر بازی اصلی افزوده می‌شود. هر User یک بازی اصلی دارد؛ Roomهای دیگر دورهای آرشیوی‌اند. مسیر قدیمی حفظ و به جریان اصلی هدایت می‌شود.

۲. حساب نام کاربری/رمز با نام نمایشی قابل ویرایش انتخاب می‌شود؛ مهمان‌بودن مالک به توکن مدیریتی و بازیابی جدید نیاز داشت و اصطکاک امنیتی بیشتری ایجاد می‌کرد. ورود ایمیلی قبلی حفظ می‌شود. بازیابی بدون ایمیل با کد بازیابی یک‌بارمصرف هش‌شده طراحی می‌شود.

۳. QuestionFactory مستقل در Application با کاتالوگ دسته‌ها، پاسخ مرجع، گزینه‌های طبیعی و shuffle امن. snapshot شامل متن پایه صاحب و سؤال غیرمستقیم دوست و نسخه موتور ذخیره می‌شود. سؤال‌های بازی منتشرشده تغییر نمی‌کنند؛ ویرایش پاسخ‌ها دور جدید می‌سازد.

۴. صفحه شروع، ساخت مرحله‌ای، بازی من/اشتراک، لینک مستقیم مهمان، نتایج و آرشیو روی Razor موجود. طراحی موبایل با design token و دو ماسکات موجود؛ اطلاعات ساخت در مرورگر تا ارسال نهایی نگهداری می‌شود.

۵. حفظ امتیاز کلاسیک برابر؛ آمار از تلاش‌های تکمیل‌شده، رتبه مشترک برای امتیاز برابر در بازی کلاسیک، نمودارهای میله‌ای سبک و قابل دسترس، کارت PNG با Canvas/فونت محلی برای ۹:۱۶. آمار نمونه تولید نمی‌شود.

۶. تست واحد موتور/امتیاز/حالت‌ها و تست یکپارچگی با دیتابیس آزمایشی؛ کنترل دسترسی، ثبت تکراری، snapshot و دورها؛ build و بررسی UI و migration.

## فایل‌های هدف

Domain: AppUser، Room، RoomQuestion، RoomEnums، RoomSettings، Participant، Ranking/TitleCatalog.
Application: سرویس مستقل PersonalGameService و QuestionFactory/کاتالوگ؛ AuthService، RoomService، StatsService، RateLimiter، DTO و DI.
Infrastructure: AppDbContext و migration افزایشی؛ جدول‌های موجود حفظ می‌شوند.
Web: صفحه شروع و layout، Account/Recovery، Game/Create/Dashboard و لینک /g؛ Join، Share، CSS/JS مرحله‌ای و کارت تصویر؛ routeهای قدیمی باقی می‌مانند.
تست‌ها و مستند اجرا/تحویل به solution اضافه می‌شوند.

نسخه بعد: AI اختیاری با fallback، مقایسه تحلیلی دورها، رادار با نمونه کافی، حالات ماسکات بیشتر و rate limit مشترک برای اجرای چندسروری. هیچ‌کدام پیش‌نیاز هسته بازی نیستند.
